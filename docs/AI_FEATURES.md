## 功能对照

| 参考项目能力 | 知岸处理方式 |
| --- | --- |
| 行测答后解析 | 接入单题页。根据用户已提交的作答、题目原文和题库解析补充讲解。 |
| 文本题库结构化 | 接入管理员导入。粘贴原文并选择分类后，生成可编辑的客观题 JSON 草稿。 |
| 学习进度顾问 | 参考仓库的运行入口已下线。本次用知岸现有近 30 天统计新增学习建议。 |
| 申论及综应批改 | 待接入主观作答、材料及评分协议。 |
| 图片识别、PDF 和图片导题 | 待接入显式上传、视觉模型和材料管理。 |
| AI 设置、提示词版本、插件技能 | 管理后台可配置共享网关，支持中转站并测试连接。提示词版本和可插拔技能待接入。 |
| 个人题库、笔记汇总、规则组卷、离线 Android | 个人题库需数据归属。笔记汇总可复用题目笔记。组卷可扩展现有模拟考试。离线端需另行设计本地存储和同步。 |

## 接口与页面

- `GET /api/v1/ai/status` 返回当前服务是否可用。答题、统计和管理导入各自处理 AI 的可用状态与错误。
- `POST /api/v1/ai/question-explanation` 接收 `{questionId, answerId}`。服务端按题号和当前用户核对作答，沿用作答快照中的答案和解析；题目正文之后被修改时提示重新作答。适用含完整文本的客观题。题库原解析先展示，AI 解析由用户点击触发。
- `POST /api/v1/ai/study-advice` 从现有北京时间统计口径读取当前用户近 30 天统计。仅传日期、科目、作答数和正确数等聚合信息。没有可用记录时提示先完成练习。输出包含样本判断和可执行的学习建议。
- `POST /api/v1/ai/question-drafts` 需管理员权限，接收 `{categoryId, sourceLabel, text}`。服务端校验分类，只发送待整理原文，生成最多 5 道客观题。沿用题目契约检查选项、答案和解析，分类和来源取人工输入。草稿默认待核验且停用，管理员审阅后添加至导入框，再通过现有事务导入流程写入。
- `GET/PATCH /api/v1/ai/settings` 和 `POST /api/v1/ai/settings/test` 需管理员权限。设置包括是否启用、网关地址、模型名、输出长度参数形式和可选 API Key。GET 仅返回 `hasApiKey`，写入时省略密钥保留同一网关的已保存密钥，显式传 `null` 清除。变更网关时需重新填写对应密钥。连接测试读取已保存配置，使用固定文本请求验证，并返回模型连通状态。
- AI 解析和学习建议复用 `RichText`，显示为独立的生成结果。操作前在页面提示将发送的数据，页面加载无需调用模型。

## 网关与数据边界

管理后台保存的配置优先。部署方也可使用 `AI_BASE_URL`、`AI_MODEL`、可选 `AI_API_KEY` 提供初始配置。全空时默认关闭。网关使用参考项目的非流式 Chat Completions 形状，接受中转站的 API 根地址（通常含 `/v1`）或完整 `/chat/completions` 地址，保留路径前缀。`AI_TOKEN_LIMIT_FIELD` 默认 `max_completion_tokens`，兼容旧网关时可用 `max_tokens`。生产网关使用 HTTPS，开发与测试可用回环 HTTP。 [OpenAI Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

普通用户只提交固定操作与业务字段。HTTP 请求转发到已保存的网关地址，拒绝重定向，限制输入、输出、单用户调用和全局并发，超时后释放并发。连接默认使用解析出的公网地址。访问私有 HTTPS 网关时，由部署方通过 `AI_PRIVATE_GATEWAY_ORIGINS` 指定允许的协议、主机和端口。邮箱、用户 ID、笔记和个人资料留在知岸，上游原始错误不会下发给前端。网关由部署方或管理员选择，接入前应确认所用题库与原文可发送给该服务。

新增一张单行配置表。后台填写的 API Key 使用 `JWT_SECRET` 派生的 AES-GCM 密钥加密。轮换 `JWT_SECRET` 后请在后台重新保存中转站 API Key。AI 生成结果只在当前页面展示，题目草稿经管理员确认后沿用原有导入流程。

## 实施顺序与验收

1. 实现网关、三种业务操作及 OpenAPI，提供开发和生产配置示例。
2. 接入答题、统计和后台导入页面，在原流程内提供独立触发与错误反馈。
3. 用本地模拟网关验收鉴权、作答归属、汇总输入、后台草稿、服务降级和浏览器交互。运行类型检查、Lint、现有测试及构建。真实模型的输出质量需在选定网关后验收。

## 启用步骤

1. 在 API 服务所在环境执行 `pnpm db:migrate`，创建配置表。原有部署脚本会应用新增迁移。
2. 以管理员访问「管理后台 → AI 设置」。填入网关根地址或完整接口地址，以及中转站提供的模型 ID 和密钥。
3. 勾选「启用 AI 功能」，点击「保存配置」后点击「测试连接」。早期兼容网关若要求 `max_tokens`，在「输出长度参数」中切换后再测试。
4. 完成一道文本题后使用「生成 AI 解析」，或在学习数据页使用「生成学习建议」。管理员可在「导入导出 → 题库」中整理原文和编辑草稿。

## 本地验收

- 类型检查、Lint、前后端构建、24 项单元与组件测试、17 项 PostgreSQL 集成测试、2 项 Chrome 端到端测试及 10 个部署模拟场景均通过。
- 使用回环 HTTP 模拟网关验证连接请求、密钥保留与跨地址隔离、作答归属、统计最小输入、重定向拦截和上游错误脱敏。浏览器验证独立配置界面和草稿审核，确认草稿经正式导入后保持待核验、停用。
- 真实中转站的连通性和模型输出质量以实际配置的连接测试和生成结果为准。
