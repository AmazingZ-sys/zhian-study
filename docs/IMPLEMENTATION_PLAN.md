## 实施顺序

先文档后共享契约和数据库，再 API 和前端纵向闭环，随后管理与发布部署、测试修复。每阶段更新此表与 TESTING.md，核对前后端字段契约。外部密钥缺失不阻塞模板和本地验证。

## 数据来源

默认无生产岗位；开发种子仅原创示例题和明确标注的虚构岗位公告。来源适配器先规范数据、校验与人工核验再发布，不内建未授权抓取。

## 部署与发布

GitHub Actions 是唯一生产入口；main 验证后 Semantic Release；同工作流 outputs 传递 tag/version/sha，并行 Vercel/GHCR。Vercel 使用仓库根目录、Node 22、锁定 CLI 65.10.0，关闭 Git 自动部署，pull/build 后上传预构建产物。手动指定包含迁移配置的已有 vX.Y.Z 重部署，不改 Release；迁移前 v1.0.0 不支持首次 Vercel 发布。Linux 宿主机 Nginx → 127.0.0.1:3000 API Docker → 独立 PostgreSQL。迁移前备份，健康失败恢复旧容器；数据库不自动回滚。

## 风险与债务管理

跨站 Cookie 受浏览器第三方 Cookie 限制，生产推荐同站自定义域名；单进程限流未来替换 Redis；专业目录版本差异需人工核验；大表统计需预聚合；定时交卷不能仅依赖前端；CI 真实运行、镜像多架构和线上恢复不可在缺少环境时宣称验证。
